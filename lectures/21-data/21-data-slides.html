Metadata

About Metadata

  • Data about the data
  • AKA: Codebook
  • AKA: Data Dictionary (not to be confused with a python dictionary) . . .

It is a comprehensive reference document that defines, structures, and explains the contents, layout, and variables of a dataset.

Metadata

  • Preferably in a text file
  • Include details
    • source, organization
    • background
    • citation*
  • Names of variables (features, atttributes)
    • As they appear in the file (usually abbreviations)
    • But also, their full name
  • Sometimes you may need to include a full description of each variable

Metadata (cont’d)

  • Recommended data types for each variable
    • boolean, integer, float, character, other
  • For categorical or ordinal variables, describe their categories
  • Missing values: how are they encoded
  • Provenance
    • How was data collected?
    • Who collected it, how was it collected it?
  • If necessary, include further details, comments, notes, for how to make sense of data, or how to treat certain values.

Three Core Rules

  1. Each variable is a column (a column contains all values that measure the same attribute).
  2. Each observation is a row (a row contains all values measured on a single unit).
  3. Each value is a cell (a cell contains a single measurement of an attribute).

FAIR Principles

FAIR

Data should be

  • Findable
  • Accessible
  • Interoperable
  • Reusable

FAIR

  • Findable: Does it have an immutable digital tracking link (DOI)?

  • Accessible: Can you download the data in 2 clicks without an institutional login?

  • Interoperable: Is the data stored in an open-source text format (like .csv), or is it trapped in a proprietary Excel format (.xlsx)?

  • Reusable: Is there an explicit Creative Commons (CC-BY) license attached, or is it unlicensed and legally untouchable?

  • Important: Just uploading files to the internet doesn’t make your science open or useful.

Share Your Data Online

  • Ideally: Deposit your data online in a well-established repository, with a permanent identifier

  • Deposit data in whatever data archive is the “go to” place for your field.

  • Better than nothing: Store it in a google drive, dropbox, box, AWS, and share a public link to it.

General Data Repositories

  • Dataverse (http://thedata.org): A repository for research data that takes care of long-term preservation and good archival practices, while researchers can share, keep control of, and get recognition for their data.

  • FigShare (http://figshare.com): A repository where users can make all of their research outputs available in a citable, shareable, and discoverable manner.

  • Zenodo (http://zenodo.org): A repository service that enables users to share research results (data and publications) that are not part of existing institutional or subject-based repositories.

  • Dryad (http://datadryad.org): A repository that aims to make data archiving as simple as possible through a suite of services not necessarily provided by publishers or institutional websites.

What about sharing data in GitHub?

  • Don’t use github for big data
  • GitHub has a limit on file size: cannot exceed 100MB
  • Many data sets can easily exceed 100MB
  • Also, be careful with binary data (Git tracks text files, not binary files)

What about sharing data through an R package?

  • Interesting option for relatively small data sets.
  • Especially good for teaching/learning purposes.
  • Example: "stat20data" package
  • Example: "janeaustinr" package
  • Example: "harrypotter" package

ROpenSci

  • Has tools and packages for accessing lots of data

Licenses

Licenses for Data

Including an explicit license with your data is the best way to let others know exactly what they can and cannot do with the data you shared.

Prefer well established licenses (or waivers) to clearly communicate the rights and responsibilities of both the people providing the data and the people using it.
