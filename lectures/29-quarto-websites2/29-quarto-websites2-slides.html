Architecture for Data Projects

When structuring a data project as a Quarto site, you typically choose between two main layouts:

A) Modular Analysis Pipeline

Break a large analysis down into logical sequence steps.

Each step becomes a separate page, accessible via the top navigation bar or a sidebar

B) The Listing / Portfolio Site

Use Quarto’s built-in Listing Pages (the engine used for blogs)

Host multiple data projects or sub-analyses in theit own blog post.


BTW: We’ll cover approach A

Example

Assume your project has the following pipeline:

  1. Data Preparation:
    • 01_data_prep.qmd
    • data_dictionary.qmd
  2. Exploratory Analysis:
    • 02_exploration.qmd
  1. Modeling:
    • 03_modeling.qmd
  2. Conclusions:
    • 04_conclusions.qmd

How to organize and present these in a website?

Integrating Data Pipelines

Data Pipelines

It’s not uncommon to work on a project that involves several data files, cleaning those files, deriving subsets from them, and then performing computations on them.

Likewise, it’s not uncommon to run simulations or modeling steps that may take some time and/or depend on external computational resources (e.g. remote servers, computer clusters, etc).

You don’t want to unnecessarily be running those computations everytime you render/preview your website.

Freeze execution (execute: freeze: auto)

Executing complex models or massive data pipelines every single time you render a site will severely slow you down.

_config.yml
project:
  type: website

website:
  # content hidden for clarity

execute:
  echo: true       # Show code by default
  warning: false   # Hide warning messahes
  freeze: auto     # freeze execution

format:
  # content hidden for clarity

Freeze execution (execute: freeze: auto)

Executing complex models or massive data pipelines every single time you render a site will severely slow you down.

  • Setting freeze: auto tells Quarto to save computational results in a _freeze/ folder.

  • Code chunks will only re-run when the source .qmd file actually changes.

  • Commit the _freeze/ folder to Git! This allows Continuous Integration platforms (like GitHub Actions) to publish your site without needing access to your raw databases or computing environment.

Script files

In addition to freezing execution, you can also include script files (e.g., .R, .py files) that take care of certain computational steps without being part of the .qmd files of your website.

In these situations you can manage everything with a Makefile, having separate rules for elements other than the website, and a special rule just for rendering the website.

Example

demo-web/
├── README.md           # Main readme file
├── _quarto.yml         # The "brain" and main config file of the site
├── index.qmd           # The homepage (rendered to index.html)
├── 01_data_prep.qmd
├── 02_exploration.qmd
├── 03_modeling.qmd
├── 04_conclusions.qmd 
├── styles.css          # Optional custom CSS overrides
├── data/               # data folder (raw, clean data sets, codebook)
├── scripts/            # folder for R/Py scripts
├── outputs/            # folder for derived outputs (might be used in qmd files)


Other files that could be necessary/worth including:

├── LICENSE             # License(s) for your project (code & media)
├── Makefile            # Rules for multiple tasks
├── environment.yml     # Conda environment
├── demo-web.Rproj      # (optional if using RStudio)
