Automatic Variables

Automatic Variables in Make

  • Automatic variables are variables that can only be used within the recipe.

  • These variables have values computed afresh for each rule.

  • Common types of automatic variables1

    • $@ the file name of the target

    • $< the name of the first dependency

    • $^ the list of all dependencies

    • $? the names of all the dependencies that are newer than the target

  1. You can find a full list of them here

A more complete Makefile

Here’s what our Makefile could look like:

Makefile
.PHONY: all clean

all: report.html report.pdf

# generate report.html
report.html: doc.qmd functions.R
  quarto render $< --output $@

# generate report.pdf
report.pdf: doc.qmd functions.R
  quarto render $< --to pdf --output $@

clean:
  rm -f report.html report.pdf

User Defined Variables

User Defined Variables

  • In addition to the automatic variables, it is also possible to create our own variables in a Makefile.

  • We’ll review 2 ways to define variables:

    • NAME = VALUE
    • NAME := VALUE

  • By convention, variable names are always written in UPPERCASE to distinguish them from file targets and commands. However, you can also write them in lowercase.

  • Likewise, variables are defined at the beginning of the Makefile.

  • To use a variable inside a target or a recipe, you must wrap its name in parentheses or braces preceded by a dollar sign: $(NAME) or ${NAME}

Example of recursive assignment =

Consider again the situation in which various md files will be assembled by pandoc into an output report.html

Makefile
# Define user variables at the top of the file
MDS = part1.md part2.md part3.md

# generate report.html
report.html: $(MDS)
  pandoc $^ -o $@

  • In this case we are using = to define MDS. This is a recursive assignment

  • The value is evaluated lazily at the exact moment the variable is used in a recipe, not when it is defined.

Example of simple expansion :=

Consider again the situation in which various md files will be assembled by pandoc into an output report.html

Makefile
# Define user variables at the top of the file
MDS := part1.md part2.md part3.md

# generate report.html
report.html: $(MDS)
  pandoc $^ -o $@

  • In this case we are using := to define MDS. This is a simple expansion

  • The value is evaluated immediately on the spot. This prevents unexpected side effects in long files.

⚠️ We may be tempted to write a Makefile like this:

Makefile
# Not exactly what we think it means
MDS = *.md

# generate report.html
report.html: $(MDS)
  pandoc $^ -o $@

Issue

Makefile
# Not exactly what we think it means
MDS = *.md

# generate report.html
report.html: $(MDS)
  pandoc $^ -o $@

  • The rule works because the pandoc command accepts wildcards *. But there’s a catch.

  • ⚠️ The issue with the above variable MDS = *.md is that a Make variable represents a string of text.

  • This means that MDS has the string value *.md instead of part1.md part2.md part3.md

Solution: Wildcard Function

To create a variable MDS that actually gathers the names of the md files, you need to use a special function in Make called the wildcard function:

Makefile
# correct way to "gather" all md files
MDS = $(wildcard *.md)

# generate report.html
report.html: $(MDS)
  pandoc $^ -o $@

A more complete Makefile

Here’s what our Makefile could look like:

Makefile
MDS = ($wildcard *.md)

.PHONY: clean

# generate report.html
report.html: $(MDS)
  pandoc $^ -o $@

clean:
  rm -f report.html
