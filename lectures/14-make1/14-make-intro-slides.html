Example: Compound Interest

Motivation

  • You deposit $1000 in a savings account
  • The annual interest rate is 2%
  • Assume interest rate won’t change
  • How much money will you have one year from now?

The answer to this question is given by the compound interest formula:

\[ \text{deposit} + \text{annual paid interest} = \text{amount in one year} \]

\[ 1000 + 1000 (0.02) = 1000 \times (1 + 0.02) = 1020 \]

Motivation (cont’d)

How much money will you have 2 years from now?

\[ \text{amount year 1} + \text{annual paid interest} = \text{amount in year 2} \]

\[ 1020 + 1020 (0.02) = 1020 \times (1 + 0.02) = 1040.40 \]


How much money will you have in 3 years?

\[ \text{amount year 2} + \text{annual paid interest} = \text{amount in year 3} \]

\[ 1040.40 + 1040.40 (0.02) = 1040.40 \times (1 + 0.02) = 1061.208 \]

Motivation (cont’d)

In one year you’ll have:

\[ 1000 \times (1 + 0.02) = 1020 \]


In two years you’ll have:

\[ 1000 \times (1 + 0.02) \times (1 + 0.02) = 1000 \times (1 + 0.02)^2 = 1040.4 \]


In three years you’ll have:

\[ 1000 \times (1 + 0.02) \times (1 + 0.02) \times (1 + 0.02) = 1000 \times (1 + 0.02)^3 = 1061.208 \]

Future Value

In \(n\) years you’ll have:

\[ 1000 \times (1 + 0.02)^n \]


Future Value formula

\[ FV = P \times (1 + r)^n \]

  • \(FV\) = Future Value
  • \(P\) = Principal (the initial deposit)
  • \(r\) = Annual rate of return (interest rate)
  • \(n\) = Number of years

About GNU Make

  • GNU Make, commonly known as make, is a Unix tool that is part of the GNU Project.

  • To work with Make you write a text file with the name Makefile, typically referred to as the makefile.

  • Notice that Makefile has not file extensions!

What’s in a Makefile?

A makefile is formed by rules that have the following structure:

Makefile
# rule
target: dependencies
  commands


  • A rule tells Make how to execute a series of commands in order to build a target file from source files (i.e. the dependencies).

  • ⚠️ IMPORTANT: the recipe line(s) must be indented with a TAB and not with any spaces.

Basic rule syntax

Under its most basic form, a rule usually has this structure:

Makefile
# rule to generate target
target: dependency
  command


  • target is the output file
  • dependency is the input file
  • command is the program that creates the target
  • the command line is indented with a TAB

Generate PDF output

What if we wanted to generate an output document in PDF format?

Makefile
# recipe to generate output file doc.pdf

  quarto render doc.qmd --to pdf


  • doc.pdf: target or output file
  • doc.qmd: dependency or input file
  • quarto render doc.qmd --to pdf: command to create target

Phony Targets

Phony Targets

  • By default, Makefile targets are file targets

  • This means that targets are used to build files from other files (i.e. the dependencies)

  • This implies that Make assumes the target of a rule is a file.

  • There are occasions, however, when a given target is not really a file, but simply the name of a recipe

  • The most common example is the all target

Phony target all

Makefile
# all outputs
all: doc.html doc.pdf

# rule 1: doc.html
doc.html: doc.qmd
  quarto render doc.qmd

# rule 2: doc.pdf
doc.pdf: doc.qmd
  quarto render doc.qmd --to pdf

  • The first target all is not the name of a file;

  • It is simply a convenient “label” to indicate a series of dependencies.

  • This type of target is known in Make terminology as a phony target.

  • Phony meaning “not a real file”.

Phony target all

The convention is to explicitly declare a phony target by making it a prerequisite of the special target .PHONY as follows:

Makefile
# declaring phony target
.PHONY: all

Declaring phony targets

Why do we declare phony targets?


Declaration of phony targets is important because of two main reasons:

  1. to avoid a conflict with a file of the same name, and

  2. to improve performance

Phony target clean

  • Another common phony target is the so-called clean target

  • This is used to indicate a recipe for “cleaning” a directory from secondary files typically generated after some compilation process.

  • Also, the clean target is also commonly used to remove output files.

Makefile
.PHONY: all clean

all: <targets>

# rule 1
...

# rule 2
...

# remove output files
clean:
  rm -f <outputs>

Phony target clean

Here’s what our Makefile could look like with phony targets all and clean:

Makefile
.PHONY: all clean

all: doc.html doc.pdf

# rule 1: doc.html
doc.html: doc.qmd
  quarto render doc.qmd

# rule 2: doc.pdf
doc.pdf: doc.qmd
  quarto render doc.qmd --to pdf

clean:
  rm -f doc.html doc.pdf

Note that clean has no dependencies. Therefore, the target clean will be always out-of-date. So whenever you run make clean, it will run independent from the state of the file system.

Various Dependencies

More than one input

Suppose we have an R script file functions.R with the code of the future value formula.

functions.R
# Title: Future Value (compound interest)
# Inputs:
# - p: principal
# - r: annual rate of return
# - n: number of years
future_value <- function(p, r, n) {
  fv = p * (1 + r)^n
  return(fv)
}

And assume that doc.qmd “depends” on functions.R. In other words, there’s a code cell in the qmd file that loads the code in functions.R

More than one input

The file structure now looks like this:

future_value/
  functions.R
  doc.qmd
  Makefile


Technically speaking:

  • doc.html now depends on both doc.qmd and functions.R
  • doc.pdf also depends on both doc.qmd and functions.R
  • If either functions.R or doc.qmd change, then the output files should be updated
